# PDF 원문 대조와 추출 품질 기록

평가일: 2026-10-28. 사용자의 자료 대신 공개 원문을 일시적으로 받아 검토했다. PDF와 렌더링 이미지 원본은 저장소에 포함하지 않는다. 아래 측정은 **소규모 탐색**으로, 전체 논문의 정확도나 사용자 문서의 성능을 보장하지 않는다.

## 방법

`inspect_pdf`로 각 PDF 전체를 추출하고 SHA-256, 물리 페이지 수, 경과 시간을 기록했다. Poppler `pdftoppm -scale-to 1600~1800`으로 지정 페이지를 렌더링해 육안으로 해당 내용과 추출 텍스트를 비교했다. 네 문구는 `locate_quote`로 지정 페이지에서 유일한 후보인지와 다른 전체 페이지에서 발견되는지 확인했다. 문구 후보는 PDF 좌표나 주장에 대한 검증이 아니다. 표와 수식은 예시 한 곳씩의 시각적 구조를 확인했으며 구조 복원 정확도를 정량화하지 않았다. 시간은 한 번의 로컬 전체 추출 경과 시간이며 CPU·메모리, 반복 측정이나 다른 파서 비교는 아니다.

## 관찰

- ResNet 물리 1쪽의 초록 첫 문장, 물리 5쪽 표 2의 34-layer 행, YOLO 물리 1쪽 초록 첫 문장, 역사 자료 물리 1쪽 첫 문구는 각각 지정 페이지에서 단일 후보였고 다른 페이지에서는 발견되지 않았다. 이는 **4개 선택 사례**이며 전체 문구 정확도가 아니다.
- ResNet 물리 5쪽의 표 2는 단순 행 값이 순서대로 추출됐으나, 표 1의 여러 셀과 수학 기호는 공백 누락·사설 폰트 글리프가 섞였다. 셀과 열의 구조를 재구성할 수 있다는 뜻이 아니다.
- Attention 물리 4쪽의 분수, 루트, 위·아래첨자는 눈으로 볼 수 있으나 추출 문자열은 배치 관계를 잃는다. 선형 텍스트를 원래 수식으로 재구성했다고 표시하면 안 된다.
- 역사 스캔의 인쇄 페이지 64는 PDF 물리 1쪽이다. 기본 텍스트 추출에는 스캔 제공자의 기존 OCR 결과가 있으며, 첫 문단 사이에 옆쪽의 소제목이 삽입되어 읽기 순서가 달라졌다. **PDF에 텍스트가 있다는 사실은 원본 디지털 텍스트이거나 OCR이 정확하다는 뜻이 아니다.** Windows 영어 OCR 언어가 설치되지 않아 별도 재인식은 `language_unavailable`로 실패했다. 기존 한국어 합성 이미지 OCR 성공과 구분한다.
- 실제 스캔의 페이지 이미지는 PDF 패턴의 XObject 안에 있어 기존 `page.images` 집계에서 0개였다. 패턴 내부 이미지를 추가 탐지하고 이미지가 있으면 텍스트가 OCR 레이어를 포함할 수 있다는 경고를 반환하도록 보강했다. PDF 리소스에는 사용하지 않은 이미지도 있을 수 있으므로 스캔 판정은 아니다.
- ResNet 2쪽에서 제어문자, 5쪽에서 사설 영역 글리프가 발견되어 추출 결과에 원문 대조 경고를 추가했다. 원문 문자를 임의로 교체하거나 삭제하지 않는다. 경고와 파서 버전은 페이지별로 저장하고 페이지 화면에 표시한다. 재처리 실패 시 이전 추출 결과와 경고는 보존한다.
- 합자 확장으로 검색할 때 원래 한 글리프의 일부만 일치해도 후보가 되던 오류를 수정했다. 온전한 원본 글리프 경계에서 시작하고 끝나는 경우만 후보로 돌려준다.

## 합성 회귀 테스트와 남은 작업

`test_pdf_processing.py`의 13개 테스트 통과. 여기에는 합성 2단·표·수식·한글 이미지 PDF, 물리 페이지·명시적 라벨·회전, 패턴 이미지 리소스, 합자 경계 및 특수문자 경고가 포함된다. 합성 자료를 실제 논문 품질 점수에 합치지 않는다.

실제 논문 10~20편 목표, 다양한 언어·출판사·복잡한 표·수식·실제 스캔 논문의 정확도 표본, 표 셀 관계 정량 평가, 실제 Windows 영어 OCR, 회전·CropBox에 대한 원문 좌표 평가, 처리 시간과 메모리 반복 측정, 대안 파서와 동일 자료 비교는 미완료다. 단 두 개의 2단 첫 페이지가 성공했다고 읽기 순서가 안정적이라고 판단할 수 없다. 허용된 원문 표본을 더 확보한 뒤 위 평가를 반복한다.
