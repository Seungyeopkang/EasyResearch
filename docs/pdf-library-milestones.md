# 현재 작업 목표: PDF·근거·개인 보관함 안정화

기준일: 2026-10-28. 사용자 요청에 따라 이번 작업은 아래 다섯 단계를 순차적으로 수행한다. 외부 논문 검색 서비스, AI 분석·논문 비교, 연구 연결과 자동 실험은 별도 후속 작업이다. 관련 기존 코드와 사용자 데이터는 보존한다.

이 문서는 작업 순서와 완료 기준을 추적하기 위한 저장소 기록이다. 앱의 goal 상태나 자동 재개 설정을 대신하지 않는다. 2026-10-28에 이 범위의 전체 goal을 새로 활성화했다.

## 공통 규칙

- 각 단계에서 구현, 관련 자동 테스트, 필요한 실제 화면 확인을 함께 수행하고 결과를 이 문서에 기록한다.
- 사용자 데이터 폴더로 파괴적 테스트를 하지 않는다. 임시 데이터와 격리된 백업 사본을 사용한다.
- 기존 PDF·메모·근거를 자동으로 덮어쓰거나 삭제하지 않는다. DB 구조 변경에는 백업, 버전별 마이그레이션, 실패 시 원본 보존과 복원 호환성 검증이 함께 필요하다.
- 문서에 적힌 기능의 존재, 실제 동작, 실제 논문 품질 검증을 각각 구분한다. 검증되지 않은 위치를 정확한 하이라이트로 표시하지 않는다.
- 최신 공식 문서와 공개 자료는 필요할 때 확인하고, 사용 조건 및 자료 출처를 기록한다.

## 1단계 — 앱 실행과 데이터 보존

**목표:** 사용자가 Windows에서 앱을 쉽게 실행하고, 자료를 안전하게 백업·확인·복원할 수 있다.

- [ ] 단일 사용자 로컬 실행 진입점을 만들고 정상 시작, 이미 실행 중인 서버, 포트 충돌, 의존성 누락과 시작 오류를 알기 쉽게 처리한다.
- [x] 백업의 대상·크기 제한·완료 여부를 설명하고 검증된 백업을 사용자가 확인할 수 있게 한다.
- [x] 별도 폴더에 복원한 자료를 확인하고 사용할 수 있는 흐름을 제공한다. 기존 보관함을 자동으로 덮어쓰지 않는다.
- [x] 데이터 구조의 버전과 마이그레이션 경로를 정의한다. 이전 버전과 현재 버전의 백업을 대상으로 성공·실패 시 원본 보존을 테스트한다.
- [x] 기존 1번 스키마를 고정해 식별한다. 지원하지 않는 미래 버전은 수정 없이 거절하고, 단계별 이관 성공 시에만 버전을 올린다.
- [ ] 잘린 백업, 잘못된 해시, 파일 누락, 저장 공간 부족 및 실행 중단 상황을 점검한다. 환경상 실제로 재현하지 못한 항목은 명시한다.

**완료 확인:** 임시 보관함에 프로젝트·PDF·발췌·메모를 저장하고, 앱을 재시작한 뒤 백업 및 별도 복원본에서 파일과 기록을 다시 확인한다. 오류 상황에서는 원본 자료가 유지되고 사용자가 다음 행동을 알 수 있어야 한다.

## 2단계 — 프로젝트 범위와 안전한 삭제·복구

**선행:** 1단계의 복원 및 데이터 구조 이관 경로.

- [x] 동일 논문이 여러 프로젝트에 있을 때 발췌와 메모의 공유 범위를 화면과 데이터 모델에 명확히 한다. 현재는 읽기 상태가 프로젝트별이고 발췌·메모가 논문별로 공유된다.
- [x] 기존 공유 기록은 임의로 특정 프로젝트에 옮기지 않고 공통 기록으로 보존한다. 프로젝트별 메모를 별도로 선택할 수 있는 방식을 마련하고 이관 결과와 공유 범위를 사용자가 확인할 수 있게 한다.
- [x] 프로젝트에서 논문 연결만 제거하는 동작과 전체 보관함에서 삭제하는 동작, 원본 파일 삭제를 구분한다.
- [ ] 프로젝트·논문·근거에 대해 연결된 기록을 확인하고 휴지통 또는 동등한 복구 경로를 제공한다. 영구 삭제는 참조와 영향을 명시한다.
- [x] 저장하지 않은 메모의 새로고침·종료 상황을 처리하고 임시 기록의 저장 범위와 복구 방식을 명확히 한다.

**완료 확인:** 한 PDF를 두 프로젝트에 연결한 경우 각각의 읽기 상태와 메모 범위를 확인한다. 한쪽에서 제외·삭제·복구하고 다른 프로젝트, 원본 파일, 이력 및 복원 백업이 의도대로 유지되는지 확인한다.

## 3단계 — 근거 출처와 상태 정확성

**선행:** 1단계의 마이그레이션, 2단계의 기록 소유·삭제 규칙.

- [x] PDF 텍스트 선택, 사용자 직접 입력, 페이지 메모, OCR 발췌의 출처와 사용자의 원문 확인 여부를 분리해 저장·표시한다.
- [x] 실제 OCR 결과가 없는데 OCR 출처로 표시되는 문제를 수정한다. 이전 데이터의 불확실한 출처는 추정해 확정하지 않는다.
- [x] 페이지 범위 오류, 문구 미일치·중복·문맥 불일치, 추출 전 상태를 사용자에게 구분해 보여준다.
- [x] 선택 문구의 앞뒤 문맥과 파일 해시·물리 페이지를 보존하고 동일 문구의 모호한 재연결은 확정하지 않는다.
- [x] 근거 수정 이력에 출처와 확인 상태를 함께 보존하며, 기존 이력의 누락된 값은 미상으로 처리한다.
- [x] 검증된 위치 좌표가 없는 경우 페이지로만 이동하며 이를 명확하게 표시한다. 정밀 좌표와 하이라이트는 별도 검증을 거쳐 추가한다.

**완료 확인:** 동일 문구의 반복, 다른 페이지, 잘못된 페이지, 사용자 메모, 텍스트 추출, OCR 및 수정 이력을 구분하는 테스트와 화면 검증을 통과한다. 실제 원문에 문구가 있다는 판정과 주장의 의미상 지지는 구분한다.

## 4단계 — 실제 논문 PDF 품질 검증과 결함 개선

**선행:** 3단계의 근거 상태와 출처. 자료 준비는 앞 단계와 병행할 수 있다.

- [x] 접근·검토가 허용된 실제 논문을 목표 10~20편 준비하고 각 파일의 해시와 출처·사용 조건을 기록한다. 연구 논문 11편을 추출했고 10편의 일부 페이지를 원문과 대조했다. 출판사·언어 다양성과 각 논문 전체 페이지는 별도 과제다.
- [ ] 2단, 표, 수식, 스캔, 혼합 페이지와 회전·다른 페이지 라벨을 가능한 범위에서 포함한다. 실제 논문과 합성 자료의 결과를 따로 보고한다.
- [ ] 원문에 확인한 발췌와 물리 페이지를 기준으로 페이지 일치, 문구 누락·중복, 읽기 순서, 표 셀 관계와 수식 기호·OCR 오류를 측정한다.
- [ ] 처리 시간·실패 이유와 측정 가능한 자원을 기록한다. 표본과 측정 방법을 함께 남기고 전체 문서의 정확도로 일반화하지 않는다.
- [ ] 발견한 결함에 회귀 테스트를 추가하고 수정한다. 기본 파서와 대안의 선택은 동일 표본의 품질·자원·설치 부담을 비교해 결정한다.

**완료 확인:** 각 유형의 원문 대조 결과와 실패 목록을 재현 가능한 형태로 보관하고, 수정 전후 비교와 남은 한계를 보고한다. 스캔·표·수식의 해석을 정확하다고 보장하지 않는다.

## 5단계 — 보관함 사용성

**선행:** 1~4단계의 데이터 보존, 기록 범위와 실제 PDF 검증.

- [x] 논문의 제목·저자·연도·DOI를 편집하고 PDF 없는 논문도 읽기 상태와 서지정보를 관리한다.
- [x] 같은 논문의 서로 다른 PDF 버전을 연결하고 동일 파일과 유사한 서지정보의 중복 후보를 구분한다. 사용자가 확인하기 전 서로 다른 파일을 자동 병합하지 않는다. 유사성 비교 범위에 한도가 있으며 추가 버전별 근거는 지원하지 않는다.
- [x] 여러 PDF의 일괄 등록과 각 파일의 성공·실패·중복 결과를 제공한다.
- [x] 읽기 상태 필터·정렬, 프로젝트별 메모와 발췌 검색을 제공한다. 공통 기록과 프로젝트별 기록의 범위를 검색 결과에도 표시한다.
- [x] PDF 본문 검색과 결과 페이지 이동을 제공하고, OCR·미추출 페이지로 인해 검색에서 누락될 수 있음을 표시한다.

**완료 확인:** PDF가 있거나 없는 논문의 정보를 편집하고, 다른 버전 및 같은 파일을 구분하며, 여러 파일의 부분 실패를 확인한다. 필터와 메모·발췌·본문 검색은 해당 프로젝트와 원문 페이지로 올바르게 이동하는지 테스트한다.

## 구현·평가 참고 자료

- [W3C Web Annotation](https://www.w3.org/TR/annotation-model/#text-quote-selector): 문구와 앞뒤 문맥을 함께 기록하는 방식. PDF에서의 정확한 위치를 보증하지는 않는다.
- [PDF.js 공식 예제](https://mozilla.github.io/pdf.js/examples/): 화면 표시를 위한 확대·회전과 좌표 변환. 위치를 저장할 때는 원본 파일과 PDF 좌표를 묶고 실제 변환을 검증한다.
- [SQLite 백업 API](https://sqlite.org/backup.html) 및 [무결성 검사](https://www.sqlite.org/pragma.html): 백업 스냅샷과 DB 무결성·외래키 검사. 파일과 DB의 연결 확인은 앱이 별도로 수행한다.
- [olmOCR-Bench](https://github.com/allenai/olmocr/blob/main/olmocr/bench/README.md): 문구, 읽기 순서, 표 관계와 수식의 평가 사례. PDF 파일 내 페이지 매칭이나 화면 좌표 검증은 별도로 필요하다.

## 진행 기록

- 기존 기본 구현과 범위는 `implementation-status.md`에 기록돼 있다.
- 2026-10-28: 백업 ZIP의 내용과 데이터베이스·PDF 무결성을 복원 전에 확인하고, 별도 폴더에 복원하는 화면을 추가했다. 기존 v1과 동일 구조의 무버전 백업은 검증된 사본을 이관하며 알 수 없는 구조와 미래 버전은 거부한다. 복원본 선택 실행 도구는 현재 서버가 종료된 상태에서만 동작한다. 임시 보관함에서 백업·복원 후 새 서버로 PDF와 메모를 읽었고, 브라우저에서 빈 백업의 생성·확인·복원 화면을 확인했다. 실제 Windows 실행 창에서 복원본 선택 및 브라우저 자동 열기 검증, 저장 공간 부족과 강제 종료 검증은 남았다.
- 2026-10-28: 백업 생성·복원 중 디스크 공간 부족을 안내하도록 추가했다. 복원 파일 일부를 옮긴 뒤 실패하는 상황도 모의 테스트하여 임시 복원본 정리와 기존 프로젝트 보존을 확인했다. 실제 디스크를 채우거나 강제 전원 차단한 검증은 아니다. 전체 자동 테스트 101개가 통과했다.
- 2026-10-28: Windows 실행 진입점과 포트·의존성·서버 준비 상태를 확인하는 테스트를 추가했다. 임시 보관함으로 서버 응답을 확인했으며 브라우저 자동 실행과 실제 콘솔의 Ctrl+C는 추가 확인이 필요하다.
- 2026-10-28: 지원하지 않는 미래 DB 버전은 초기화·저널 변경 전에 거부하는 보호와 격리 DB 테스트를 추가했다. 무버전 DB의 구조 호환성 검사, 원자적 마이그레이션과 이전 백업 이관은 아직 구현되지 않았다.
- 2026-10-29: v1~v4 이관과 이관 전 스냅샷, 지원하지 않는 DB 구조의 백업 거부, 복원 중단 표식을 구현했다. v1·v2·v3 백업을 격리된 경로에서 이관·복원하고 원본 보존을 확인했다. 저장 공간 부족과 중단은 모의 검증이며 실제 전원 차단은 수행하지 않았다.
- 2026-10-29: 프로젝트별 메모, 논문 공통 발췌, 프로젝트·논문·근거 및 연결 휴지통, 메모 충돌 감지, 메모·발췌 임시본 복구를 추가했다. 격리 보관함을 두 브라우저 탭에서 열어 메모 충돌, 최신 내용 비교, 새로고침 뒤 임시 메모 복구를 확인했다. 브라우저의 탭 복제 기능 자체는 확인하지 못했다.
