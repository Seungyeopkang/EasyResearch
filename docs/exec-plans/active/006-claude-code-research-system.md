## 1. 사용자 결정 (2026-11-10)

- 연구, 갭 찾기, 아이디어, 검증은 모두 **Claude Code(구독)**가 맡는다.
- 로컬 모델(Ollama)은 논문 장단점 같은 가벼운 정리에만 쓴다.
- 데스크톱 전용이다. 모바일 화면은 고려하지 않는다.
- 재귀 개선은 연구 과정의 **에이전트 간 대화**에도 적용한다.
- 실험 자동화는 나중에 설정한다. 다만 연구와 실험은 자연스럽게 이어져야 하므로, 연결 지점(실험 계획서)은 이번에 만든다.
- 중간 승인은 사용자가 단계마다 켜고 끌 수 있어야 한다.
- 검증자는 기여, 문제 정의, 정확성을 냉정하게 평가하고, 말이 안 되는 결과를 걸러내야 한다.

## 3. 역할 분담

### 3.1 연구 시스템 에이전트 (`.claude/agents/*.md`)

공식 필드(`name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`, `memory`, `effort`, `color`)만 쓴다.

| 이름 | 모델 | 역할 | 도구 (허용 목록) | 쓰기 권한 |
|---|---|---|---|---|
| `research-lead` (메인 대화 역할, 11.1 참조) | Opus, effort high | **총괄**: 주제 해석, 연구 계획, 단계 진행, 되돌아가기 결정, 승인 정책 확인, 최종 보고 | Agent, MCP 읽기·주기 도구, Read | 연구 주기 상태, 초안 |
| `literature-scout` | Haiku | **문헌 탐색**: 검색어 설계(여러 관점), MCP 검색, 중복 제거, 1차 선별(포함·제외 이유), 인용 따라가기 | MCP `search_literature`, `get_related` | 없음 (결과만 반환) |
| `paper-analyst` | Sonnet | **정밀 읽기**: 서재 논문 본문(페이지)에서 문제·방법·한계·향후 과제를 구절·페이지와 함께 추출 | MCP `get_page_text`, 프로필 읽기 | 프로필 초안 |
| `hypothesis-builder` | Sonnet | **대안·기여 생성**: 근거와 실패 기록, 교훈 목록을 읽고 대안 방법 2–4개와 기여 가설을 만든다 | MCP 읽기, 실패 기록·교훈 읽기 | 가설 초안 |
| `verifier` | Opus, 작성자와 다른 맥락 | **냉정한 검증**: 기준표 평가, 반증 시도, 선행 연구 대조, 탈락·보완·통과 판정 | MCP 읽기, `search_literature`, `verify_quote` | 판정 기록만 |
| `citation-checker` | Haiku | **정확성 점검**: 모든 주장의 인용 구절이 원문에 있는지, 주장과 맞는지 확인 | MCP `verify_quote`, `get_page_text` | 없음 |
| `lesson-curator` | Sonnet | **재귀 개선**: 주기가 끝나면 검증자의 반박과 작성자의 수정 대화를 정리해 교훈을 덧붙이고, 스킬·프롬프트 개선 제안을 만든다 | 실패 기록·교훈·평가 결과 읽기 | 교훈 덧붙이기만. 스킬 변경은 제안만 |

공통 규칙:
- 연구 에이전트에는 `WebFetch`, `WebSearch`, `Bash`를 주지 않는다. 외부 접근은 앱 MCP 도구(OpenAlex 예산·캐시 포함)로만 한다.
- 하위 에이전트를 부를 수 있는 것은 `research-lead`뿐이다. 깊이는 1이다. 공식 기본값은 3단계까지이지만 이 시스템은 1단계만 쓴다.
- 모든 에이전트에 `maxTurns` 상한을 둔다.
- `verifier`는 가설을 쓴 에이전트의 대화를 받지 않는다. 최종 산출물과 근거만 받는다.

## 4. 연구 주기 (단계와 되돌아가기)

```
주제 ─▶ ① 계획 ─▶ ② 문헌 탐색 ─▶ ③ 정밀 읽기 ─▶ ④ 대안·기여 가설
                                                   │
          ┌──────────── 실패 기록에 남김 ◀──탈락──┤
          │                                        ▼
          └─▶ ②나 ④로 되돌아가기 (횟수 상한)   ⑤ 검증 (검증자 + 인용 점검)
                                                   │ 통과
                                                   ▼
                                     ⑥ 기여 확정 (사람 승인 선택)
                                                   ▼
                                     ⑦ 실험 계획서 (잠금) ─▶ (나중) 실험 단계
                                                   ▼
                                     ⑧ 보고 + 교훈 정리 (재귀 개선)
```

- **되돌아가기 규칙** (코드가 강제):
  - 가설 하나당 2회, 주기 전체에서 10회까지 되돌아갈 수 있다.
  - 근거가 부족하면 ② 문헌 탐색으로 돌아간다.
  - 가설에 결함이 있으면 ④ 가설 생성으로 돌아간다.
  - 같은 이유로 2회 탈락하면 해당 방향을 닫고 사람에게 묻는다.
- **실패 기록**
  - 덧붙이기만 하고 수정하지 않는다.
  - 항목 필드: 이유 코드, 근거, 만료일, 사용자 해제 여부.
  - ④단계는 생성 전에 반드시 읽는다.
- **예산**: 시간, 호출, 되돌아가기 횟수에 상한을 둔다. ExecPlan 005의 장치를 다시 쓴다.

## 5. 검증자 설계 (말이 안 되는 결과 걸러내기)

1. **기준표 평가.** 항목마다 근거 인용이 필수이고, 점수 대신 통과·보완·탈락으로 판정한다.
   - 문제 정의: 실제로 열려 있는 문제인가, 근거 논문에 그렇게 적혀 있는가.
   - 기여의 실체: 무엇이 새로 가능해지는가. 단순 조합이나 이름만 바꾼 것인가.
   - 정확성: 인용한 구절이 원문에 있고 주장과 맞는가. `citation-checker`와 코드의 `verify_quote`로 확인한다.
   - 선행 연구와의 차이: 가장 가까운 선행 연구 3편과 무엇이 다른가. 다르지 않으면 탈락이다.
   - 실현 가능성: 필요한 데이터, 자원, 평가 방법이 있는가.
2. **반증 시도.** 통과시키기 전에 먼저 깨뜨려 본다.
   - 반례 검색, 반대 결과를 보고한 논문 검색, "이미 했다"는 증거 검색.
   - POPPER 방식: 예상 결과를 먼저 적고 고정한다.
3. **자동 탈락 (코드가 강제).** 아래 경우는 모델 판단과 상관없이 탈락이다.
   - 근거 인용이 없다.
   - 인용이 원문과 맞지 않는다.
   - 가장 가까운 선행 연구를 검색하지 않았다.
   - 같은 실패 이유가 실패 기록에 이미 있다.
4. **독립성.**
   - 검증자는 Opus로 작성자와 다른 맥락에서 돌며, 가설 작성 과정의 대화를 보지 않는다.
   - 같은 모델 계열이라는 한계는 남는다. 그래서 탈락 사유는 반드시 확인 가능한 근거로 쓰게 한다.
5. **사람 몫.** 참신성 최종 판단과 기여 확정은 사람이 한다. 승인 정책에서 켜고 끌 수 있다.

## 6. 재귀 개선 (에이전트 간 대화 포함)

- **대화 기록**: 검증자 반박 ↔ 작성자 수정, 인용 점검 결과, 사람 피드백을 주기 기록에 남긴다.
- **교훈 목록** (`lesson-curator`)
  - 반복되는 실패 패턴을 "이런 가설은 이런 이유로 탈락했다" 형태로 덧붙인다 (ACE·ReasoningBank 방식).
  - 교훈 수에는 상한이 있다. 오래되거나 효과 없는 교훈은 사용자가 정리한다.
  - 다음 주기의 `hypothesis-builder`와 `verifier`가 읽는다.
- **스킬·프롬프트 개선**
  - `lesson-curator`는 변경 제안만 만든다.
  - 채택하려면 **숨겨진 평가 세트**에서 기존보다 나아야 한다. 이 세트는 고정 주제 10–20개와 기대 점검 항목으로 이루어지며, 개선하는 쪽은 읽을 수 없다.
  - 비교는 블라인드 A/B로 하고, 그다음 사람 승인을 받는다.
- **보호 영역**: 아래는 사람 승인 없이 바꿀 수 없다. 훅으로 강제한다.
  - 평가 세트와 평가 코드.
  - `.claude/` 설정·훅.
  - `AGENTS.md`.
  - `data/`.
  - 백업 코드.

| 대안·가설 목록 | 확인 | 자동 | 자동 |
| 검증 탈락 후 되돌아가기 | 확인 | 자동 (상한) | 자동 (상한) |

| 스킬·프롬프트 변경 | 확인 | 확인 | 확인 (끌 수 없음) |

- 승인은 단계 사이에서만 받는다. Claude Code 작업 도중에는 멈출 수 없기 때문이다.

## 8. 앱 쪽 변경 (MCP와 데이터)

- **새 MCP 도구**: 모두 앱 API를 거친다. 외부 전송은 앱의 예산·캐시·기록을 그대로 쓴다.
  - `search_literature` (OpenAlex 검색).
  - `get_related`: 인용 따라가기 (`referenced_works`, `cites:`).
  - `verify_quote`: 코드로 원문을 대조한다.
  - 연구 주기: 만들기, 상태 조회, 단계 기록.
  - 실패 기록: 읽기, 덧붙이기.
  - 교훈 목록: 읽기, 덧붙이기.
  - 승인 정책: 읽기. 쓰기는 사람만 한다.
  - 승인 대기 등록.
- **스키마 v8**
  - 새 표: `research_cycles`, `cycle_events`(대화·판정 기록), `failure_ledger`, `lessons`, `gate_policy`, `experiment_plans`.
  - v7 → v8 이관은 스냅샷을 만들고, 백업·복원 호환을 점검한다.
- **화면**
  - 연구 주기 보기: 단계, 판정과 탈락 이유, 되돌아가기 내역.
  - 승인 대기 목록, 정책 설정, 실패 기록·교훈 관리.
- **실험 계획서**
  - 담는 내용: 가설, 기준선, 지표, 데이터, 예상 결과, 실패 기준.
  - 잠그면 해시를 기록하고 바꿀 수 없다. 나중에 실험 단계가 이 계획서만 입력으로 받는다.
- **기존 앱 연구 루프 (ExecPlan 004·005)**: "오프라인 모드"로 남긴다. 기본 경로는 Claude Code이다.
- **로컬 모델**: 논문 장단점 빠른 정리에만 쓴다.

## 10. 수용 기준 (초안)

- **AC1** Claude Code에서 프로젝트 에이전트 7종과 스킬이 인식된다. MCP 서버가 연결되어 서재 읽기와 초안 쓰기가 실제로 된다.
- **AC2** 연구 에이전트는 허용 목록 밖의 도구(WebFetch, Bash 등)를 쓸 수 없다. 보호 영역 쓰기는 훅이 막는다.
- **AC3** 검증자가 근거 없는 가설, 원문과 맞지 않는 인용, 선행 연구와 같은 가설을 탈락시킨다. 탈락 이유는 실패 기록에 남는다.
- **AC4** 탈락하면 규칙대로 되돌아가고, 상한을 넘으면 사람에게 묻는다.
- **AC5** 승인 정책의 기본 묶음 세 가지와 단계별 설정이 동작한다. 끌 수 없는 항목은 끌 수 없다.
- **AC6** 교훈은 덧붙이기만 된다. 다음 주기 프롬프트에 들어가고, 스킬 변경은 평가 세트를 통과하고 승인을 받아야 적용된다.
- **AC7** 실험 계획서는 잠금 후 바뀌지 않는다 (해시 일치).
- **AC8** v7 → v8 이관 전에 스냅샷을 만들고, 백업·복원과 기존 테스트가 통과한다.

### 11.2 MCP: 우리 서버 안에 직접 구현

- **외부 MCP 서버를 쓰지 않는다.** 앱의 예산·캐시·기록을 건너뛰기 때문이다.
  - 외부 서버는 설계 참고용으로만 본다.
  - Sci-Hub 옵션이 있는 서버, 쓰기 권한이 있는 AGPL Zotero 서버, Google Scholar 수집기는 쓰지 않는다.
- **도구**: 서버 이름 `easyresearch`. 권한 규칙 이름은 `mcp__easyresearch__<도구>`이다.
  - 문헌: `search_literature`, `get_related`.
  - 원문 대조: `verify_quote`. 페이지 번호가 어긋나면 이웃 물리 페이지를 1회 더 확인한다.
  - 연구 주기: `research_cycle_create`, `research_cycle_get`, `research_cycle_append_event`.
  - 기록: `failure_ledger_read`, `failure_ledger_append`, `lessons_read`, `lessons_append`.
  - 승인: `gate_policy_get`, `approval_request`, `approval_status`.
  - 초안 저장: `save_hypothesis_draft`, `record_verdict`.
  - 이름은 M2에서 M 보고서와 N 보고서의 표기를 하나로 맞춘다.
- **응답 규칙**: 페이지 나눔, 크기 상한, `isError` 오류. 문서 텍스트는 untrusted 필드에 담는다.

### 11.4 검증자 규칙 (N 보고서 3.5, 3.8)

- **자동 탈락**: 앱 코드가 먼저 검사하며, 하나라도 걸리면 바로 탈락이다.
  - A1 근거 없음.
  - A2 인용이 원문에 없음.
  - A3 선행 연구 검색이 3회 미만.
  - A4 실패 기록과 같은 이유.
  - A5 예상 결과의 수치 기준이 없거나 나중에 바뀜.
  - A6 "최초", "선행 연구 없음" 같은 참신성 단정.
  - A7 초록·메타데이터 근거(A1·M)만으로 기여를 주장함 (12.1).
- **기준표**: 각 항목은 통과·보완·탈락 중 하나이며 근거 ID가 필수이다.
  - C1 문제가 실제로 열려 있는가.
  - C2 기여가 구체적인가. 이름만 바꾸거나 단순히 합친 것은 탈락이다.
  - C3 인용이 정확한가.
  - C4 가장 가까운 선행 연구 3편과 각각 무엇이 다른가. 하나라도 차이가 없으면 탈락이다.
  - C5 반증할 수 있는가.
  - C6 실현할 수 있는가.
  - C7 내부적으로 일관되는가.
- **반증 검색**: 통과 판정 전에 반대 결과나 "이미 같은 기여를 한 논문"을 최소 1회 검색한다.
- **토론 규칙 (작성자 ↔ 검증자, 최대 2라운드)**
  - 반박에는 근거 ID가 있어야 한다.
  - 작성자는 반박마다 수정, 새 근거, 인정, 근거 있는 반론 중 하나로만 답한다.
  - 기준이나 수치 기준은 바꿀 수 없다.
  - 모든 발언은 `cycle_events`에 기록되고 `lesson-curator`가 읽는다 (재귀 개선 입력).
- **숫자 점수는 없다.** 이유 코드만 쓴다. 그래야 실패 기록을 다시 쓸 수 있다.

### 11.5 에이전트 기억

- 공식 `memory` 필드는 쓰지 않는다.
- 교훈과 실패 기록은 사람이 관리하는 앱 DB(MCP)에 둔다.
- `.claude/agent-memory/`는 보호 영역 안에서 검토 없이 쓰이는 공간이 되므로 피한다.

### 12.1 본문 확보 (구멍 1)

- **기존 기능 재사용**: 앱의 `POST /api/papers/{id}/fetch-open-pdf`(ExecPlan 003)를 MCP 도구 `fetch_open_fulltext`로 노출한다.
  - 지금은 검색 결과 PDF → arXiv → OpenAlex 공개 위치 순서로 시도한다.
- **흐름**: 선별된 논문 → 서재로 가져오기 → 공개 PDF 받기 → 텍스트 추출 작업 → `paper-analyst`가 정밀 읽기.
- **확장 순서**: OpenAlex `best_oa_location`·`locations` → arXiv 직접 → OpenAlex 콘텐츠 다운로드 → Unpaywall → Semantic Scholar `openAccessPdf` → CORE → Europe PMC.
  - 모두 실패하면 초록만 쓴다.
  - Unpaywall 이후는 M2에서 한도와 약관을 확인한 뒤 추가한다.
- **한도**
  - arXiv: 약관에 따라 3초에 1회 요청한다.
  - OpenAlex PDF 다운로드: 무료 키 기준 하루 약 100편이다 (100 credits/파일, $1 = 10,000 credits. 2026-11-10 실제 호출로 1 credit = $0.0001 확인).
  - 주기당 가져오는 편수 상한: 20편 (제안). 승인 정책으로 자동 또는 확인을 고른다.
- **근거 강도 표시**

  | 표시 | 뜻 |
  |---|---|
  | `F1` | 본문, 공개 라이선스 |
  | `F2` | 본문, 라이선스 불명확 |
  | `A1` | 초록만 |
  | `M` | 메타데이터만 |

  - **`A1`·`M` 근거만으로는 기여를 주장할 수 없다** (자동 탈락 A7로 추가).
- **라이선스**
  - 라이선스가 불명확한 PDF(bronze 등)는 이 PC에만 보관하고 내보내기·공유에서 뺀다.
  - 원본 PDF는 덮어쓰지 않는다 (기존 불변 규칙).
- **실패 처리**
  - PDF 대신 랜딩 페이지가 오거나, captcha·유료벽이 있거나, 크기 초과면 그 소스를 건너뛴다.
  - 실패 이유는 기록하고, 사람에게 직접 PDF를 넣어 달라고 요청할 수 있다.

### 12.2 종료와 재계획 (구멍 2)

- **"기여 찾음" 판정**: 아래를 모두 만족해야 한다.
  1. 검증자 통과.
  2. 자동 탈락 규칙(A1–A7)에 하나도 걸리지 않음.
  3. 가장 가까운 선행 연구 3편 대조.
  4. "이미 같은 기여가 있다"는 반대 방향 검색.
  5. 모든 인용이 원문과 일치 (`citation-checker`).
  6. 같은 가설 카드를 다시 검증해도 판정이 같음 (2회 일치, 제안).
  7. 사람 승인. 승인 정책 "대부분 자동"에서는 보고서 표시로 대신한다.
- **정체 감지** (하나라도 걸리면 재계획)
  - 새 관련 논문 고갈: 최근 검색 2라운드에서 새로 포함된 논문이 0편이다 (제안). 체계적 문헌고찰의 SAFE 중단 규칙을 하한으로 참고했다. Callaghan의 분석상 단순 규칙만으로는 재현율 목표를 못 맞출 수 있다.
  - 진척 없는 반복: 정체 카운터가 2를 넘는다 (Magentic-One 기준 ≤2).
  - 가설 개선 정체: 3회차 이후 통과·보완 판정이 늘지 않는다 (Nova: 약 3라운드 이후 개선 정체).
- **재계획 4종**
  - 주제 넓히기, 주제 좁히기, 다른 관점 검색(방법·데이터·평가 축), 다른 문제로 전환.
  - 주기 전체에서 합쳐 5회까지 (제안).
  - 같은 종류는 연속 2회까지만 한다.
- **예산 상한** (모두 제안값, 승인 정책 화면에서 조절)
  - 실행 시간 4시간.
  - 서브에이전트 호출 60회.
  - 되돌아가기: 가설당 2회, 전체 10회.
  - 참고: AI Scientist v2는 전체 약 15시간, Kosmos는 12시간·200회 실행이다.
- **못 찾음 보고서**: 필수 8항목.
  1. 주제와 범위
  2. 시도한 방향
  3. 탈락 가설과 이유 코드
  4. 근거 강도 분포
  5. 남은 유망 방향
  6. 정체 감지 기록
  7. 쓴 예산
  8. 사람에게 필요한 결정

  | 교훈·실패 기록 | lesson-curator, 코드 | hypothesis-builder, verifier | DB (덧붙이기만) |
  | 실험 계획서 (잠금, 해시) | 메인 (`experiment-plan`) | 나중의 실험 단계 | DB |
  | 승인 기록 (지점, 결정, 시각) | 메인 | 감사 기록 | DB |

- **지시문 형식**: 목표, 입력 ID 목록, 출력 형식, 허용 소스(앱 MCP만), 한도, 반환해야 할 근거 ID.
- **완료 영수증**: 서브에이전트는 끝날 때 다음을 돌려준다.
  - 만든 산출물 ID와 건수.
  - 실패 항목.
  - 썼던 호출 수.

### 12.4 긴 실행 이어가기와 사용량 (구멍 4)

- **상태 저장 위치**
  - 진행 상태(주기 ID, 마지막 완료 단계, 대기 중인 승인, 예산 사용량)는 앱 DB에 둔다.
  - Claude Code가 대화를 압축하면 `CLAUDE.md`는 다시 읽히지만, 진행 중인 연구 상태는 남지 않는다. 그래서 DB가 기준이다.
- **재개**: `/research resume <주기ID>`
  1. DB에서 상태를 읽는다.
  2. 마지막 완료 단계 다음부터 진행한다.
  3. 대기 중인 승인이 있으면 먼저 묻는다.
  - 같은 단계를 두 번 실행해도 산출물이 겹치지 않는다. 단계 ID와 입력 해시로 확인한다.
- **훅** (이름은 공식 문서로 확인함)

  | 훅 | 용도 |
  |---|---|
  | `SessionStart` (압축·재개 포함) | 진행 중인 주기 요약을 `additionalContext`로 넣는다 |
  | `PreCompact` | 압축 전에 현재 단계를 DB에 기록한다 |
  | `PostCompact` | 압축 후 상태를 다시 넣는다 |
  | `SubagentStop` | 완료 영수증을 확인하고 기록한다 |
  | `StopFailure` | 실패를 기록한다 |
  | `PreToolUse` | 보호 영역 쓰기와 허용 외 도구를 막는다 |

- **사용량 정책**
  - 구독 한도는 5시간 단위와 주간 한도가 있다는 구조만 공식 확인되며, 숫자는 공개되지 않았다.
  - 단계별 모델: 탐색·인용 점검은 Haiku, 읽기·가설·교훈은 Sonnet, 검증과 메인은 Opus.
  - 주기마다 서브에이전트 호출 상한을 둔다 (12.2).
  - 실행 중 사용량을 확인하고, 한도에 가까우면 현재 단계를 마친 뒤 멈춘다. 이어서 할 명령을 남긴다.

### 12.5 M1에서 실제로 시험할 것

- 사용 한도에 걸렸을 때 Claude Code의 동작.
- 훅 패턴(matcher) 문법.
- 압축 후 AGENTS.md를 다시 읽는지.
- 서브에이전트의 백그라운드 기본 동작.
- `PreToolUse`에서 호출한 에이전트를 식별할 수 있는지.
- 스킬 `allowed-tools` 형식.
- 미리 불러온 스킬의 동작.

## 13. 미해결 질문

- 연구 주기는 Claude Code 대화 안에서 진행하고 앱 화면에서는 기록과 승인만 볼지, 앱에서 Claude Code 작업을 시작하는 버튼도 둘지 정해야 한다.
  - 버튼을 두려면 `claude -p` 비대화 모드를 써야 하는데, 구독 로그인에서 동작하는지 확인이 필요하다. `--bare` 모드는 API 키가 필요하므로 쓰지 않는다.
- 숨겨진 평가 세트의 주제를 사용자가 정할지, 서재에서 자동으로 고를지 정해야 한다.
