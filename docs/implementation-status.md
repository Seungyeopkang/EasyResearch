# 구현 현황과 다음 작업

기록일: 2026-10-28, Asia/Seoul. 아래 내용은 현재 저장소와 이 PC에서 확인한 결과다. 외부 서비스 정책이나 설치 환경은 달라질 수 있다.

현재 사용자 승인 범위와 순서는 [PDF·보관함 단계별 작업](pdf-library-milestones.md)을 따른다. 이 문서의 이전 전체 기능 목록은 기존 현황과 후속 작업 참고용이다.

## PDF·보관함 안정화 진행 상황

- 백업 검사, 별도 복원 및 복원본 실행, v1~v5 스키마 이관과 이관 전 스냅샷, 파일·DB 무결성 및 복원 중단 표시를 구현했다. 지원하지 않는 DB 구조는 백업 성공으로 표시하지 않는다.
- 프로젝트별 메모와 논문 공통 발췌를 구분하고, 프로젝트·논문·근거와 프로젝트 연결을 휴지통에서 복구할 수 있다. 메모 동시 수정은 충돌을 알리고 내용을 비교한 뒤 저장한다. 미저장 메모와 발췌는 브라우저 임시본으로 보존하며 앱 백업에 포함되지 않는다.
- 발췌 출처와 원문 확인 상태, 물리 페이지, 앞뒤 문맥, PDF 해시와 수정 이력을 저장한다. PDF 텍스트의 줄 끝 하이픈으로 이어지는 문구는 별도 후보로 표시한다. 새 OCR 발췌는 당시의 OCR 결과를 보존하며 기존 결과 미상 기록은 추정하지 않는다.
- PDF 없는 논문의 직접 등록과 서지정보 수정, 유사 중복 후보, 로컬 메모·발췌·본문 검색, 읽기 상태 필터, 다중 PDF 등록 및 추가 버전 보관·이름 수정·휴지통 복구를 제공한다. 추가 PDF 버전의 발췌와 읽기 기록은 기본 원본에 연결되며, 추가 버전별 근거는 아직 지원하지 않는다.
- 공개 논문 11편을 추출하고 10편의 일부 페이지를 원문과 대조한 기록은 [최초 평가](pdf-quality-evaluation.md), [추가 평가](pdf-quality-followup.md), [스캔과 추출기 비교](pdf-quality-scan-and-parser-comparison.md)에 있다. 실제 스캔 논문 2편의 기존 OCR 오류도 확인했다. 표·수식의 구조나 2단 읽기 순서, PDF 좌표는 보장하지 않는다. 여러 출판사와 언어, 실제 스캔의 새 OCR 인식, 대안 파서의 동등 조건 비교와 실제 Windows 복원 실행 창 확인은 남았다.

- 2026-11-08: 휴지통 영구 삭제(영향 미리보기·확인 토큰), 백업 손상 재현 테스트, BBT 방식 citekey, CSL-JSON·W3C 주석 JSON-LD·Obsidian 노트 내보내기, Obsidian 볼트 동기화 스크립트(`scripts/sync_obsidian.py`), 읽기 전용 MCP 서버(`services/mcp/`), 딥링크와 키보드 단축키를 추가했다. 세부 기록은 [ExecPlan 002](exec-plans/completed/002-library-completion-and-integrations.md)에 있다. MCP 서버는 실제 MCP 클라이언트와의 stdio 연결을 확인하지 않았고, `mcp` 패키지는 앱과 다른 `starlette` 버전을 요구해 별도 가상환경이 필요하다.

## 현재 동작

- 단일 사용자 로컬 웹앱: 프로젝트 생성, PDF 등록·해시 기반 중복 처리, PDF 없는 검색 논문에 PDF 연결, 읽기 상태·마지막 앱 페이지 기록.
- 로컬 PDF.js 뷰어에서 한 페이지씩 원본 확인과 글 선택, 해당 페이지의 발췌·메모, 근거 변경 이력, PDF 텍스트 추출 및 작업 상태. 추출한 구절이 원문에 있다는 사실과 그 구절이 주장을 지지하는지는 별개다.
- Windows와 Poppler·언어 팩이 준비된 환경에서 페이지별 Windows OCR. 결과는 `ocr_unverified`로 표시하며 합성 한글 스캔 PDF로 실제 실행했다. 사용자가 원문 확인을 명시하고 OCR 텍스트에서 일치가 확인된 발췌는 그 출처를 표시하여 분석에 사용할 수 있다.
- OpenAlex·arXiv 검색, Crossref DOI 조회, 검색 기록. 외부 통신 오류를 표시한다.
- 근거 선택과 로컬 발췌 비교, 선택적으로 OpenAI에 발췌를 보내는 분석. 외부 전송 전 내용을 미리 보여주고 미리보기와 내용이 달라지면 거절한다. 여러 논문의 자동 우열은 매기지 않는다.
- 근거에 연결된 아이디어, 입력·코드 해시와 시드가 기록되는 고정 CPU 기준선, 선택적 Codex 제안 및 제한된 Docker 실행 경로.
- 아이디어의 제목·설명·상태와 근거 연결을 수정하거나 아이디어만 삭제할 수 있다. 기존 근거를 불러오지 못하면 편집 화면에서 저장을 막는다. 프로젝트 이름과 설명도 수정할 수 있다.
- 프로젝트의 Markdown·BibTeX·JSON 내보내기, SQLite 스냅샷과 파일 해시를 포함하는 백업, 복원 전 백업 내용과 무결성 확인, 별도 경로 검증 복원 및 복원본 선택 실행.
- Windows 작업 프로세스와 하위 프로세스를 Job Object로 묶어 종료하고 시도별 임시 파일을 정리한다. 오래된 작업의 DB 결과 반영은 토큰으로 막는다.
- PDF 재처리와 OCR은 원본 크기·해시를 처리 전후에 확인한다. 일부 페이지의 재추출이 실패하면 기존 결과와 근거를 보존하고, 저장된 발췌 문맥이 일치하지 않으면 분석에 쓰지 않는다.

## 확인한 내용과 한계

- 합성 PDF의 2단·표·수식·이미지 페이지와 실제 Windows OCR, Windows 작업 프로세스 종료, API 통합과 백업·복원 자동 테스트를 실행했다. 테스트 수와 최신 결과는 다시 실행해 확인한다.
- 임시 보관함을 이용한 실제 브라우저에서 프로젝트 생성, PDF와 근거, 아이디어, CPU 기준선, 백업 생성과 별도 폴더 복원을 확인했다.
- PDF.js 6.2.108을 로컬에 포함했다. 한 번에 한 페이지만 표시하고 텍스트 선택 시 해당 페이지와 문구를 입력한다. 이미지 페이지와 글꼴이 깨진 문서는 직접 확인이 필요하며, 저장한 구절 위치의 정밀 하이라이트는 없다. 기본 표시·글 선택과 페이지 이동은 합성 PDF로 브라우저에서 확인했다.
- 이전 5.6.205는 [Mozilla 보안 권고](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j)의 영향 버전 범위에 들어 공식 npm의 수정판 6.2.108로 교체했다. XFA와 평가 코드도 명시적으로 끈다. 악성 PDF 재현 및 복잡한 실제 논문과 다양한 브라우저의 호환성 검증은 수행하지 않았다.
- 일반 추출은 `pypdf`이며 구조화된 표·수식과 다단 읽기 순서를 보장하지 않는다. Docling 어댑터는 존재하지만 설치·UI 작업 경로와 실제 논문 벤치마크는 아직 완성되지 않았다.
- 합성 PDF 결과를 실제 학술 논문 10~20편의 성능으로 일반화할 수 없다. 표·수식·스캔, 회전, 라벨, 좌표가 포함된 실제 자료의 품질 측정이 필요하다.
- 이 환경의 외부 네트워크 제한으로 검색과 OpenAI는 모의 응답·오류 테스트를 수행했다. 실제 API 연결 및 모델 품질을 검증하지 못했다.
- Docker CLI는 존재하지만 확인 시 Docker 엔진에 연결되지 않았다. 생성 코드의 컨테이너 실행은 명시 요청과 로컬 이미지가 필요하며 실환경 실행을 검증하지 못했다.
- Codex 제안 어댑터는 실행 기능이 비활성인지 확인하지 못하면 차단한다. 확인 당시 설치된 CLI는 `unified_exec` 비활성 상태를 보고하지 않아 제안 호출을 차단했다. 실제 Codex 제안과 그 결과의 실험 연계는 완성되지 않았다.
- Windows 이외의 플랫폼에서는 OCR과 작업 프로세스 트리 정리가 동일하게 검증되지 않았다. 페이지별 파서 버전과 경고를 보존하지만 처리 모델과 모든 설정에 대한 완전한 이력은 아직 없다.
- SQLite v1~v5와 호환되는 무버전 v1 구조의 이관을 지원한다. 확인되지 않은 구조나 미래 버전은 거부하며 이후 버전이 생기면 해당 이관 단계를 별도로 구현·검증해야 한다.

## 이어서 할 일

1. 실제 접근 가능한 논문 10~20편을 모아 페이지·구절·표·수식·다단·스캔을 사람과 대조하고 파서 속도·메모리·실패를 기록한다.
2. Docling을 별도 프로세스의 선택적 작업으로 통합하고 결과·옵션·모델 버전별 이력을 보존한다. 원본 좌표가 확인된 경우에만 페이지 하이라이트를 제공한다.
3. PDF.js 뷰어의 줌·회전·CropBox·여러 줄 선택 좌표를 실제 논문으로 검증하고, 검증된 구절 위치의 하이라이트를 추가한다.
4. 사용자 확인을 거친 OCR 발췌의 실제 논문 표본과 여러 언어에서 일치·중복 판정을 검증한다.
5. 네트워크가 허용된 환경에서 OpenAlex·arXiv·Crossref와 OpenAI를 실제로 확인하고 검색 품질·요금·오류 처리를 측정한다.
6. Codex 공식 연동에서 도구 실행 권한을 안전하게 제어하는 방식을 검증하고, Docker 실행 환경에서 생성 코드의 격리·취소·재현을 테스트한다.
7. 수정된 PDF.js의 복잡한 실제 논문과 다양한 브라우저의 표시·선택 및 보안 회귀를 확인한다. 읽기 기록 관리, 작업 이력 UI, 검색/실험 평가와 백업 스키마 마이그레이션을 추가한다.

앱 사용법과 테스트 명령은 [README](../README.md), 상세 목표와 품질 기준은 [구현 우선순위](implementation-decisions-and-reference-review.md) 및 [PDF 설계](pdf-reading-and-evidence-design.md)를 참조한다.
